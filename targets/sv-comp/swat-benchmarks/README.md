# swat-benchmarks

Local SV-COMP-style tasks that measure where SWAT's static pre-analysis (SA) pruning helps, and
whether it stays sound. Results and findings: [RESULTS.md](RESULTS.md).

Layout is the same as `sv-benchmarks/java/`: `java/<suite>/<task>/Main.java` with
`java/<suite>/<task>.yml` next to it, `common/` (Verifier, ObjectFactory) and `properties/` copied
from the main suite. Only `valid-assert.prp` is used. `_true` tasks are SAFE, `_false` tasks are
VIOLATION.

## Suites

All tasks are generated by `scripts/gen.py`; the sources are committed so they can be read and
diffed, the `.class` files are not (they are gitignored repo-wide) and are built by
`scripts/build.sh`.

Benefit families (`scripts/families.py`), each variant for n in {2, 4, 8, 16, 32} (dead-callees:
1..6, irrelevant-prefix: 2, 4, 6, 8), SAFE and VIOLATION. Every task has the same single assertion,
`target(a, b)`: three nested input-dependent branches, satisfiable in the VIOLATION variant
(a = 1001, b = 2996) and not in the SAFE one (it differs in one comparison).

| suite | shape | variants |
|---|---|---|
| `dispatcher` | `cmd` picks one of n commands; n-1 handlers with 4 independent branches (16 paths), the last command calls `target` | `switch`, `ifchain`, `instance` (instance methods), `loop` (two dispatch rounds: the event-loop shape) |
| `validation-gauntlet` | n checks `if (v_i < i) reject`, then `target` behind two calls | `return`, `report` (3-branch error report, then return), `throw` (caught in main), `exit` (`System.exit`) |
| `error-handling` | n steps, each in try/catch; the catch logs (3 branches) and returns; `target` on the success path | `explicit` (throw one frame down), `deep` (two frames), `arith` (implicit ArithmeticException), `bounds` (implicit AIOOBE) |
| `dead-callees` | n helpers with 2 branches each, on paths that cannot reach `target` | `suffix` (after `target`), `guarded` (`if (mode == 1) {...; return;}`), `shared` (the same helper is also called before `target`: needs a context-sensitive walk) |
| `virtual-dispatch` | `cmd` selects one of n subclasses; only the last `run()` calls `target` | `local` (`new Ci().run()`: exact receiver), `factory` (receiver returned by a switch: ambiguous call), `array` (receiver read from an array) |
| `irrelevant-prefix` | control: n independent `if (x_i > 0) count++;` before `target` | `count` |
| `exception-dispatch` | the command is parsed from input `t`; for `t < 0` parsing throws, the handler derives the command from `t` too, then a `dispatcher/switch` (measures what SA loses after an exception it does not model) | `npe` (a NullPointerException: SA gives up after it), `explicit` (control: an explicit throw, modelled precisely) |

`sa-soundness` (`scripts/soundness.py`): hand-written SAFE/VIOLATION pairs around constructs where
the graph and the executor can disagree (arrays from JDK calls, implicit and unguarded exceptions
across frames, static initializers, String/enum switch, try/finally, object `==`, lambdas,
streams, reflection, recursion, default methods, anonymous/inner classes, `synchronized`), plus
narrowing tasks added after the first runs (`*-noarg`, `library-throw-catch`, `cce-catch-up1`,
`explicit-throw-generic-catch`, `clinit-unconditional`) and executor reproducers (`exec-*`). In
every pair the assert is `if (x > 1000 && x < HI) assert false;` with HI = 100000 (VIOLATION) or
1001 (SAFE), and it is only reached after flipping an input-dependent branch that the risky
construct sits on. Each task's comment says what it tests.

`real-tools` (`scripts/tools.py`, harnesses in `scripts/tools/`): harnesses around unmodified
GNU java-getopt 1.0.13 (`getopt-minitar`, a tar-like CLI) and opencsv 2.3's `CSVParser`
(`opencsv-import`). The tools are not in the repository: `scripts/fetch_tools.sh` downloads their
sources from Maven Central into `java/real-tools/lib-*/` (gitignored), which the tasks list on
their `input_files`.

## Build, check, run

```bash
cd targets/sv-comp/swat-benchmarks/scripts
./gen.py                 # regenerate sources and .yml files (all suites, or name some)
./fetch_tools.sh         # only for real-tools
./build.sh               # javac --release 8 -g:source,lines, classes next to the sources
./check_labels.py        # check every label by running it (see below)

./run_configs.sh                              # SA, --no-sa and --sa-rank-distance runs of everything
CONFIGS="sa nosa" ./run_configs.sh --suite dispatcher   # TIMEOUT (300) and WORKERS (48) via env
./compare.py ../../runs/run_A ../../runs/run_B [--only-diff] [--csv out.csv]
../../scripts/.venv/bin/python3 report.py ../../runs/run_SA ../../runs/run_NOSA --out ../report
```

`run_configs.sh` refuses to start while another SV-COMP run is live, builds first, and runs
`svcomp test run --mode parallel --no-witness --categories valid-assert.prp --benchmark-dir
swat-benchmarks` (paths relative to `targets/sv-comp`). `compare.py` prints, per task and run, the
result, wall time, rounds, solver calls and the DFS visits from `explorer.log` (how many had a
pruned side, and how many had no SA node because the walker gave up).

## How the labels were checked

`check_labels.py` runs every task with `-ea` against a stub `Verifier` (`scripts/stub/`) that
replays chosen inputs. The inputs are in each task's header comment.

- VIOLATION: the violating inputs must fail an assert. All do.
- SAFE: the paired VIOLATION task's inputs must not fail (the minimal difference is what makes it
  safe). That the task is safe for all inputs is argued in its header comment: for the families,
  `target` needs b = 3a - 7 < a with 1000 < a < 100000, i.e. a < 3.5 (no overflow in range); for
  the soundness pairs, `x > 1000 && x < 1001` has no int solution; the tool harnesses say why.
- Every task: all inputs 0 (SWAT's first round) reach no assert, so each violation needs at least
  one flipped branch. The gauntlet's `exit` variant exits there instead, which is allowed.
